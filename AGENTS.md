# Проверка изменений дизайна

07.11.2026 опубликована beta.204: Windows x64, macOS Apple Silicon и веб.
Публичный тег `v0.4.0-beta.204`, исходники клиента `c659552`, ветка
`release/video-covers-beta204`. В ней объединены Архив/Избранное и все клиентские
правки резервирования beta.203. Следующий preview — не ниже beta.205.
Рабочий API beta.50 включает обложки VK через oEmbed с maxwidth=1280/maxheight=720;
данные и файлы обновления синхронизированы на резерв. Результат выпуска —
`docs/RELEASE_BETA_204.md`.

07.11.2026 владелец проверил Windows-предпросмотр beta.204 и явно разрешил
общий выпуск для всех: Windows x64, macOS Apple Silicon и веб. В выпуск входят
обложки YouTube/Rutube/VK под ссылкой, Архив/Избранное возле плюсика и все
проверенные изменения резервирования beta.203. Основную левую панель сохранять;
изолированный тестовый ChatsPage без AccountSidebar не является её новым дизайном.

07.11.2026 опубликована beta.203 для Windows x64, macOS Apple Silicon и веба
с выбором резервного endpoint. Исходники релиза и автоматики находятся в ветке
`infra/automatic-reserve-203`, коммит `b17487e` (публичный тег
`v0.4.0-beta.203`). До выпуска beta.204 ветка beta.202 содержала не опубликованные
«Избранное»/«Архив»: не выпускать её как beta.202 поверх beta.203 и не терять
проверенные клиентские изменения резервирования при следующем выпуске.
Перед следующим preview перенести/объединить изменения из публичной ветки,
сохранив эти новые функции, и использовать номер не ниже beta.204.
Production: Москва `185.225.201.129` — основной; Петербург `191.44.38.60` —
синхронный резерв. Автопереключение включено с независимым Cloudflare-арбитром
и fencing HOSTKEY. Актуальная инструкция — `docs/AUTOMATIC-FAILOVER.md` в
публичной ветке. Не применять старые ручные `pg_promote`/clone-сценарии без
приостановки автоматики и согласования владения с арбитром.

По просьбе владельца сначала передавайте отдельную Windows-сборку локальным
файлом для просмотра любых изменений дизайна. Общий релиз и обновление рабочего
сайта с этим дизайном выполняйте только после его явного одобрения.

Для TRLKA не использовать skill unslop и не следовать его рекомендациям,
если владелец явно не попросит об этом снова. Сохранять прежний яркий дизайн.
