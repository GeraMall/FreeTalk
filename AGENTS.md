# Проверка изменений дизайна

08.11.2026 новый покер подготовлен как Windows-preview beta.207 в ветке
`preview/poker-table-beta207`: сукно и анимации, таймер 30 секунд, три докупки,
панели комбинаций/статистики, видеопортреты. Статистика только текущего стола —
явный выбор владельца. Подробности — `docs/PREVIEW_BETA_207.md`.
Новые правила включаются отдельным pokerRules=2 при создании стола и не должны
менять уже идущие старые партии. Публичный клиент остаётся beta.205; общий
выпуск нового дизайна не разрешён до проверки предпросмотра.

08.11.2026 подготовлены исправления покера и переподключения в ветке
`fix/poker-and-replication-beta206`. Публичный клиент остаётся beta.205;
следующий предпросмотр beta.206. Контроллер HA учитывает свежесть reply_time
за 20 секунд, сохраняя обязательное снятие eligibility через арбитр перед
асинхронными записями. Сигналинг 0.1.11 совместим с клиентом beta.205.
Подробности и разбор инцидента — `docs/PREVIEW_BETA_206.md`.

При публикации установщиков обязательно запускать
`node scripts/release/verify-download-links.mjs`: проверять не только номер
папки релиза, но и полное имя файла в каждой кнопке сайта, HTTP 200 и ответ
с установщиком вместо HTML. В beta.205 исправлена ссылка, где папка была 205,
а имя файла оставалось 200; граница regex `\b` не срабатывает перед `_`.

07.11.2026 опубликована beta.205 для Windows x64, macOS Apple Silicon и веба.
Тег `v0.4.0-beta.205`, исходники `848acb7`, ветка `release/shared-games-beta205`.
Общий планшет содержит шесть игр, лобби и курсоры; новые игровые таблицы
используют activityVersion=2. Проверенные Архив/Избранное, видео и резервирование
beta.204 сохранены. Следующий preview — не ниже beta.206.
Результат выпуска — `docs/RELEASE_BETA_205.md`.

07.11.2026 подготовлен приватный Windows-preview beta.205 в ветке
`preview/shared-games-beta205`: новые игры, лобби и курсоры. Владелец проверил
предпросмотр и 07.11.2026 явно разрешил общий выпуск beta.205 для Windows x64,
macOS Apple Silicon и веба. Подробности — `docs/PREVIEW_BETA_205.md`.
Production signaling уже 0.1.10 с согласованием activityVersion=2; старые
клиенты beta.204 сохраняют прежний протокол. Владелец отдельно разрешил
краткое переподключение текущего звонка для этой установки; это не является
общим разрешением на перезапуски при активных звонках.

07.11.2026 опубликована beta.204: Windows x64, macOS Apple Silicon и веб.
Публичный тег `v0.4.0-beta.204`, исходники клиента `c659552`, ветка
`release/video-covers-beta204`. В ней объединены Архив/Избранное и все клиентские

Рабочий API beta.50 включает обложки VK через oEmbed с maxwidth=1280/maxheight=720;

07.11.2026 владелец проверил Windows-предпросмотр beta.204 и явно разрешил
общий выпуск для всех: Windows x64, macOS Apple Silicon и веб. В выпуск входят
обложки YouTube/Rutube/VK под ссылкой, Архив/Избранное возле плюсика и все
проверенные изменения резервирования beta.203. Основную левую панель сохранять;

07.11.2026 опубликована beta.203 для Windows x64, macOS Apple Silicon и веба
с выбором резервного endpoint. Исходники релиза и автоматики находятся в ветке
`infra/automatic-reserve-203`, коммит `b17487e` (публичный тег
`v0.4.0-beta.203`). До выпуска beta.204 ветка beta.202 содержала не опубликованные
«Избранное»/«Архив»: не выпускать её как beta.202 поверх beta.203 и не терять
проверенные клиентские изменения резервирования при следующем выпуске.
Перед следующим preview перенести/объединить изменения из публичной ветки,
сохранив эти новые функции, и использовать номер не ниже beta.204.
Production: Москва `185.225.201.129` — основной; Петербург `191.44.38.60` —
синхронный резерв. Автопереключение включено с независимым Cloudflare-арбитром
и fencing HOSTKEY. Актуальная инструкция — `docs/AUTOMATIC-FAILOVER.md` в
публичной ветке. Не применять старые ручные `pg_promote`/clone-сценарии без
приостановки автоматики и согласования владения с арбитром.

По просьбе владельца сначала передавайте отдельную Windows-сборку локальным
файлом для просмотра любых изменений дизайна. Общий релиз и обновление рабочего
сайта с этим дизайном выполняйте только после его явного одобрения.

Для TRLKA не использовать skill unslop и не следовать его рекомендациям,
если владелец явно не попросит об этом снова. Сохранять прежний яркий дизайн.
