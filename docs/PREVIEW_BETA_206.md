# Предпросмотр beta.206: покер и устойчивость соединения

Владелец сообщил о недоступном повышении ставки в партии на четверых,
пинге около 2000 мс, зависших действиях и уведомлении об отсутствии интернета.
Проблему наблюдали на Windows и Mac. Публичный клиент остаётся beta.205;
beta.206 подготовлена как отдельный Windows-предпросмотр.

## Разбор инцидента

Журналы 8 ноября 2026, примерно 00:10–00:12 по Москве, показывают сбой частной
связи между Москвой и Петербургом. Петербургский прокси получал таймауты
соединения с основным узлом, а API Москвы исчерпал пул ожидающих соединений
PostgreSQL. Синхронные записи ожидали подтверждения резерва. WAL sender завершил
зависшее соединение в 00:11:19; автоматика отключила ожидание синхронного резерва
в 00:11:20 после снятия его права на повышение. В 00:12:28 синхронная репликация
восстановилась. В тот же период зарегистрированы переподключения участников.

Это подтверждает инфраструктурную причину сетевой части инцидента. Первое
недоступное повышение ставки не удалось привязать к конкретному игровому
действию: содержимое раздач и нажатий в production-журнал не записывается.
Отдельно воспроизведены и исправлены ошибки ввода суммы и открытия повышения.

## Исправления

- Контроллер HA требует свежего подтверждения репликации за последние 20 секунд,
  вместо ожидания одного лишь снятия статуса streaming после 60-секундного
  таймаута. Снятие права резерва через арбитр обязательно предшествует разрешению
  асинхронных записей. При недоступном арбитре строгая синхронность сохраняется.
- Запоздавшее действие планшета получает актуальный персональный снимок игры.
  Снимки ограничены по частоте и не раскрывают карты других игроков.
- В поле ставки можно очистить значение и последовательно набрать новую сумму;
  промежуточные цифры больше не заменяются немедленно минимальной ставкой.
  Неверные и дробные значения не отправляются.
- Чек сохраняет право повысить короткий открывающий олл-ин. Несколько коротких
  олл-инов вместе могут вновь открыть повышение для уже ответившего игрока.
  Один неполный олл-ин сохраняет ограничение; уравнять или сбросить карты можно.
- Вскрытие при олл-ине обоих блайндов сохраняет корректный номер места в снимке,
  чтобы клиент не отвергал ответ из-за отрицательного индекса хода.

## Проверки и развёртывание

Общий `pnpm check` прошёл: клиент 448, API 140, сигналинг 35 тестов; прошли также
протокол и остальные пакеты. Отдельно пройдены 15 проверок безопасности HA.
Сценарии повышения покрывают четырёх игроков; проверены приватный resync,
ограничение повторов, сохранение фишек и валидность снимка олл-ина.
Условия свежести подтверждения проверены SELECT-запросом PostgreSQL для
текущего времени, 10 секунд, 21 секунды и отсутствующего подтверждения.
Реальную репликацию для испытаний не прерывали.

Контроллер обновлён на обоих узлах. Совместимый со старым клиентом сигналинг
0.1.11 установлен после проверки отсутствия активных комнат. API и база
не перезапускались. Публичные установщики, веб-клиент и автообновление
не переключались на beta.206.

Сигналинг 0.1.11 и исправленный контроллер синхронизированы на резерв.
После установки оба узла прошли мониторинг, репликация streaming без
отставания. Арбитр сохраняет владельца Moscow, epoch 3, строгую синхронность
и отсутствие fencing. Найденный сбой не воспроизводили искусственным
отключением production-сети; следующая проверка — реальная партия на четверых.
