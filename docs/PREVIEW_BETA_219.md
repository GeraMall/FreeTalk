## Оформление и настройки

В «Интерфейс» добавлены космическая (прежняя), светлая и чёрная темы.
Выбор хранится локально в `trlka.interface-theme`, не зависит от системной темы.
Исходные цвета оставлены fallback для прежней темы; новые палитры используют
общие роли поверхностей, текста, границ и состояний. Изображения не инвертируются.
Вход, регистрация и welcome всегда тёмные, сохранённая тема применяется после
входа. Выход из аккаунта не стирает локальный выбор.

«Ваша карточка в звонке» перенесена из профиля в «Интерфейс», изменения
применяются сразу. Шрифт сброса настроек совпадает с выходом из аккаунта.
У светлой темы один тонкий разделитель sidebar/чата и плавный верхний угол.
Восстановлены прежние выбранная подложка и hover выделенных сообщений,
увеличенная область click beta.218 остаётся; текст и действия не перехватываются.

Монополия получила отдельное розово-лиловое лобби, зелёное сукно сохранено.
У светлых пастельных денежных чисел тонкий тёмный stroke без светлой тени.
Каталог игр в светлой теме имеет тёмный текст и светлые плитки; игровые
поверхности с собственными цветами карт/сукна сохраняют тёмное окружение.
У «Завершить для всех» анимированный power-значок, у прежних стрелки/X —
отдельные небольшие анимации без изменения формы. Reduced motion соблюдён.

## Переводы

Статические подписи шести игр, правила, лобби, комбинации, подсказки,
московские улицы и карточки переведены на en/zh-CN/kk/be/ka/es;

сгенерированных ботов переводятся отдельно. Вопросы викторины связаны
с исходными RU/EN вариантами без изменения порядка ответов.

Аудит 30 файлов игровых компонентов/контента: отсутствующих ключей 0
(`outputs/doc-review/game219-final-audit.txt`). Сторонний переводчик
использовался только для статических строк исходников, без данных пользователей.

## Синхронизация: реализована, на сервер НЕ установлена

Подготовлены API beta.53, миграция `030_appearance_preferences.sql`,
GET/PUT `/v1/me/appearance` и клиентский контроллер. Новый аккаунт по
умолчанию имеет `syncEnabled=false`. При включении выбранная тема
записывается только в собственный аккаунт; другие устройства получают её
при входе, фокусе или видимом 60-секундном опросе. PUT последователен,
старые ответы не отменяют новый выбор, ошибка не стирает локальную тему.
API требует авторизацию, проверяет поля и ограничивает частоту записи.

Автоматическая проверка разрешений дважды отклонила подготовку сценария
развёртывания (`rejected: blocked by policy`), в том числе после явного
разрешения пользователя «Да, установить синхронизацию». Подробная причина
не указана. Удалённых изменений не выполнялось; сценарий
`outputs/doc-review/theme219-deploy.py` не создан. Отказ не обходился.
API production остаётся beta.52, signaling 0.1.19, миграция 030 не применена.
Дополнительное пользовательское разрешение уже дано, повторно его не запрашивать.

Preview честно показывает недоступность синхронизации и блокирует её
переключатель до успешного ответа нового endpoint. Локальные темы работают.
Клиент сможет обнаружить установленную серверную часть при следующем опросе.
Проверки восстановления резерва после установки не проводились, так как
сама установка не состоялась. Состояние HA не изменялось.
