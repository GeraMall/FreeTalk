# Предпросмотр beta.199: звук демонстрации всего экрана

Пользователь сообщил об обратной передаче голосов участников в режиме «Экраны» с включённым звуком на Windows beta.198. В режиме «Окна» проблема не проявляется.

До изменения WASAPI исключал дерево PID `freetalk.exe`. Теперь у вызывающего WebView запрашивается фактический `BrowserProcessId` через WebView2 API на UI-потоке, и WASAPI исключает эту группу процессов с её аудиослужбой. Это устраняет предположение, что общий WebView2 обязательно запущен текущим Rust-хостом. По документации Microsoft одна группа WebView2 может использоваться несколькими средами/хостами с общим профилем.

PID определяется до запуска захвата. При ошибке или тайм-ауте приложение не подменяет фильтр общим системным миксом. Режим окна продолжает включать дерево процесса выбранного окна; закрытое окно с PID 0 отклоняется. Выключенная галочка звука не запрашивает WebView2 PID и не запускает аудиозахват.

Проверена изоляция WASAPI на двух отдельных синтетических звуковых процессах: исключение первого сохраняет сигнал второго. Сам звонок пользователя и его микрофон для проверки не использовались. Сохранены только агрегированные уровни сигнала, без записи звука. Воспроизведение именно пользовательского эха в beta.198 и проверка исправления в его живом звонке пока не выполнены.

Включена компактная и более тонкая панель старых сообщений из локальной beta.198. Общий выпуск beta.199 не выполнялся.

Нативные release-тесты: 8 прошли, 3 аппаратных теста оставлены ignored. Отдельная проверка двух синтетических WASAPI-процессов выполнена вне этих тестов.
