## Изменения

Убраны конфликтующие правила сетки чата комнаты. Пузырь своего сообщения больше
не попадает в колонку аватарки шириной 30px; аватарки остаются в первой строке.
Свои сообщения и реакции справа, чужие слева, зазор реакций 3px.
Проверены 24 сочетания разрешений/тем/стилей с CSS готовой сборки.

На Mac политика сохранения разрешения применяется также в режиме «Видео».
После согласования видеоканала и подключения параметры отправителя применяются
повторно. Это не меняет настройки камеры и политику демонстрации Windows.
Собственная адаптация TRLKA продолжает снижать битрейт/FPS/масштаб при плохой сети;
постоянные 1080p/60FPS при любом соединении не обещаются.

Известные проблемы: повторный запуск демонстрации на некоторых Mac может
оставаться на чёрном превью с загрузкой; системный звук на Mac также требует
диагностики. Этот выпуск не объявляет эти два сообщения исправленными.
Ограничение включено в описание релиза и updater notes.

## Отдельное исправление сайта: восстановление пароля

После запуска выпуска владелец сообщил, что «Забыли пароль?» отключена при вводе
ника. Веб-hotfix `7811583` открывает восстановление при пустом логине, обычном нике
и @username; запрашивает email отдельным шагом. Запрос кода не отправляет username,
не дублируется при повторном клике, при ошибке остаётся на шаге почты, при успехе
открывает существующий ввод кода/нового пароля. Отдельный вход с уже готовым кодом
сохранён. Используются существующие переводы всех семи языков и стили TRLKA.

Полный pnpm check для hotfix прошёл: desktop551/API155/protocol139/signaling46/
CF15/admin2; целевые WelcomeScreen/BrowserPlatformGate — 17 тестов.
Backend восстановления не менялся, настоящие письма в проверках не отправлялись.
Установщики beta.223 из тега32893df этого дополнительного исправления не содержат;
оно подготовлено для веба и включения в следующий нативный выпуск>=224.
Веб-hotfix опубликован атомарно и синхронизирован с резервом. Полная HTTP-проверка
подтвердила HTML/JS/CSS из production-сборки7811583. В браузере на 1280×800 и
390×844 проверены пустой логин, neman и @neman: кнопка активна, поле почты очищено
от ника, запрос кода доступен только после email. Реальные письма не отправлялись.
Кнопка главной страницы запустила загрузку правильного EXE, тестовая загрузка отменена.
Финальные HA monitor прошли; PID и время старта API/сигналинга не менялись,
PostgreSQL streaming/sync, резерв остаётся в recovery.

Владелец отдельно уточнил, что присланный Invalid input был после просроченного кода.
Срок восстановления на сервере20минут. Сам код/пароль не запрашивались и не сохранялись.
Backend и правила кодов в этом web-hotfix не менялись; не приписывать сообщению
Invalid input точную причину без данных запроса.
Его резервная копия отдельная: `/root/trlka-ha/release223-auth` (не затирает backup221).

Журналы: `outputs/doc-review/release223-*`, подписи проверяются по существующему
